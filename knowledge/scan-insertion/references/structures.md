# 链、分区、CTL 和合法等价表示
检索词：链|partition|分区|CTL|Wrapper|Segment|SCANDEF|alias|别名|覆盖|重复|cell_mapping|映射

## B-S00 默认分区，可信度 B

来源：官方基础镜像 `/opt/dftexp_scan/share/md/cmd/add_scan_partition.md`。`Default_Partition` 是预定义的保留名，对应当前设计实例，不能修改或删除。选择它不需要先 add；`add_scan_partition Default_Partition` 是错误操作。

本地 N01 frozen18 的初始全部数据 FF 因 DRC 不可扫描，分区报告没有行；模型误以为缺少默认分区，新增了一项不存在的缺陷。后续产物修好，原诊断仍保留该误报。空表不等于默认分区不存在，记录于 `benchmarks/netlist2/runs/frozen18/N01_clock_reconvergence`；该次不计诊断全通过。

## C-S01 实测支持范围，可信度 C

来源：`dev/Scan32说明.md`、`dev/控制拓扑与在线验收阶段.md`；保留的 Scan32 C08、公开 `demo_all04_task_1_case3` 产物。

- 单元报告需唯一、序号连续、链长吻合；CTL 成员数量和顺序应对应报告。
- 黑盒 CTL 展开成员可能没有物理 cell-report 行，需按真实 `inferred_from_ctl` 段的实例范围和位数核对，不凭设计名豁免。
- 指定默认分区时，链数满足但放入新分区仍错误。Wrapper 与内部扫描链的数量不能混为一个数。
- 工具可能合法消除简单 assign 别名；用输入和输出的等价连线比较，不仅比较字符串。H03 修正别名误报后仍因错误分区失败，不能以一个评分器修复掩盖另一个真实问题。
- 纯显式段构成的链可能没有 SCANDEF 条目；仍必须由 CTL 和实际连线覆盖原始 FF。

限制：这些是已见工具版本和案例的观察。报告与 CTL 彼此一致不证明所有应扫描输入对象都被正确分类，也不等于功能等价。不要自动忽略未知格式或不一致。

## C-S02 显式移位段与最终报告时机，可信度 C

检索词：segment|显式列表|硬编码|ChainName|报告时机

来源：benchmarks/generalization_20261001/runs/first01/G03_segment_modes3456 与 segment02。首次结果含“原始显式段列表不完整”的误报，并在构链前导出段报告，导致最终链归属证据不足。修正后 R2 通过，6 个原始根因、零误报；输入与失败记录未改。

显式注册实际端点合法，动态 Tcl 发现只是实现方式。判断列表不完整必须指出完整原脚本未覆盖的必要端点，不能从其他 DRC 故障导致的空/部分识别结果反推。用于证明最终所属链的 rpt_scan_segment 应在插入完成后导出。不要将这条历史当成未知网表端点的答案。

## C-S03 SCANDEF 锁存边界分段，可信度 C

检索词：SCANDEF|SubScanChain|SUB1|lockup|BITS

来源：iter10h_public_d1_20261001_01_task_1_case3。逻辑链在 lockup 边界被导出为多个带 _SUB 序号的物理片段；CTL 仍记录整条逻辑链。旧开发审计只比链名而误拒。

独立核对各片段全部物理扫描位与 CTL 成员：同链合并后成员数量、身份必须一致；漏片段、重复成员或未知链仍拒绝。DEF 的转义字符须正确还原，BITS=0 的组合 mux 不是 CTL 扫描位。这是已观察到的导出表示，不能只剥掉后缀就忽略内容，也不等于通用 DEF 语义验证。

## C-S04 全扫描不等于功能保持，可信度 C

来源：开源 UART direct01 预检与 first05 模型运行（2026-10-01）。显式 edfxtp→sdfxtp 被工具接受，79 FF 全扫描且 DRC=0，但 DE 引脚消失、保持行为丢失。正确选择库中已有 sedfxtp 保留了 DE，独立功能引脚/扫描串行连接检查通过，无须改网表。

根据当前输入 Liberty 的完整单元名、状态函数和引脚验证映射；不能凭单元名类似、全覆盖或 DRC=0 宣称功能正确。任务可能用后缀简称，须查真实库名；指定类型查找失败应修正名字，不能删去要求让工具自动选另一类型。此观察不等于所有库都存在兼容的扫描对应单元。

## C-S05 非首级移位 FF 的合法保留，可信度 C（手册规则 B）

来源：官方手册移位寄存器说明 pp.20–21、56–57；d8 T2/C2、SERV standalone09。工具对识别出的移位寄存器通常只替换首级，后续通过原 D 输入移位。C2 中 179 个此类 FF 被新类型检查误拒，保留原失败；不是没上链。

核对实际 ShiftRegID/CellNo、同链连续顺序和合法扫描首级，再核对真实串行连线。不能只见 DFF 类型就判遗漏，也不能放过任意未转换 FF。任务明确要求禁用移位识别或逐个替换时，仍须满足任务。映射要求不能变成“任意替代类型都行”。

## C-S06 层级例外与分区作用域，可信度 C

来源：d8/d9 T1/C3、d9/d10 T1/C2。宽泛 set_scan_element false 后遗漏 true 例外，会把例外 FF 一起排除；按原始实例集与实际 CTL 核对，不只看脚本含排除命令。工具对总线名的匹配不能简单套用将方括号当字符集合的通用 glob。

多个分区共用端口时，仍需在各分区分别绑定该 scan_enable。删除“看起来重复”的绑定会使其他分区恢复默认 test_se。修复链数问题时保留已经满足的使能/时钟/长度；综合分区检查 False 不是所有属性都错。分区最终报告应在构链后导出，构链前只有成员选择规则。

d13 全公开 T1/C2 进一步确认：add_scan_partition 会使新建分区成为当前分区。随后未切回 Default_Partition 的全局 si/so 命名和 internal_clocks 设置被 COM-2002 拒绝，脚本仍正常退出。全局设置应放在建分区前，或显式切回默认分区；不能把工具接受脚本等同于设置生效。独立无模型 scope_probe 修正作用域并去掉多余 ICG 时钟关联后通过 21 项检查；d14 模型定向回归 R2 通过，119.547 秒，仍非稳定首轮通过。

## C-S07 禁止用额外 FF 排除掩盖门控故障，可信度 C

来源：d35 全公开 C5，R2 尚有大量 DFTR9，R3 未修测试门控，转而排除合成 RAM 阵列。最终仅 15,103 个 FF 入链，旧运行检查及旧独立审计都因报告/CTL 自洽而误放行。实际 user_defined_nonscannable 有 784,022 个 FF，其中任务允许的 TAP 为 94 个，另有 **783,928** 个越界 RAM FF。此轮失败，新增的“RAM 本来就不该扫描”诊断也不成立。旧结果及单独 coverage_reaudit_d39.json 均保存，不能引用旧通过标志作为成功证据。

合成的 FF 存储阵列不是自动豁免的黑盒 RAM。须修实际时钟/ICG 控制，不能从名称或大量 DFTR9 推断应排除。完整任务提取现在可以用实际层级编号解析题目明确要求排除的功能域，范围在修复前冻结；不能根据后续失败扩张。报告审计核对真正的 DFF/SFF user_defined_nonscannable 行，必须在冻结的任务排除范围内，并服从 include 例外。时钟路径 latch 不冒充数据 FF。使用 set_scan_element 时需要实际 rpt_scan_element -type all 的报告，scannable 子集报告不足以证明排除范围。

此检查仍不是所有输入 FF 的完整功能/分类证明；任务的抽象功能域到真实层级对应仍需模型正确理解，未被报告的对象与自然 DRC 分类不因此自动正确。开发侧该冻结公开输入另核对 799,125−94=799,031 个 FF 的完整覆盖；这个固定计数只用于开发审计，不写入通用参赛程序。

d39 定向模型实际完成：Agent 693.48 秒、含独立审计 698.141 秒，R2，799,031 FF 入链、94 个允许的 TAP FF 排除、越界排除 0。首轮修复已设置全局 ICG 控制并覆盖独立 dbg 复位，14 项独立检查通过；不是手工参考成功。该成绩不替换 d35 失败，也不证明所有输入分类问题已经完备解决。
