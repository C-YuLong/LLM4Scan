# 诊断与证据
检索词：诊断|根因|位置|路径|漏报|误报|masked|violated_requirement|original_command|DFTR

## A-D01 评分约束，可信度 A

来源：赛题指南第 15～17、25～30 页。定位要指向真实命令/参数/端口/实例/网表结构；只复述错误不算根因。一个根因导致多个后续错误只算一个；不同参数独立错误即使共享一行，也要分别说明。中间误判可自动纠正，最终以正确诊断为准。

## C-D02 已见失败，可信度 C

来源：`benchmarks/control6/runs/frozen14/H07_reset_mode/`、`repair17_diagnosis/H07_reset_mode/`。

H07 同时修复复位 off_state 和 mode 常量，却只报告一个根因。以原始失败检查与明确任务值为依据检查遗漏，才触发一次诊断纠正。不要从“修改了某行”直接推断该行原本有错；显式默认值、路径迁移、额外报告导出都可能只是实现差异。

H04 成功运行的诊断文字重复一层 node41；真实脚本引用没错也不等于自由文本路径正确。最终输出对象位置应使用能核对的源文件行与具体语句；保留模型原始描述供审计，不对历史运行结果悄悄改字拿分。

## 边界

引用能证明“该语句存在”，不自动证明模型的因果解释正确。还要结合原始失败、任务和连线；修复后成功本身不能反证每个原始指控成立。静态证据不能伪装成原始工具已报出的错误。

## C-D03 报告读取与默认值误报，可信度 C

检索词：file join|默认值|报告缺失|误报|lockup|usage

来源：2026-10-01 的 iter10h_transfer_20261001_01 与 iter10h_artifact_paths_20261001_01，见 dev/十小时迭代记录_20261001.md。旧产物解析器漏读原脚本用 file join 导出的报告，将实际正确的默认设置误记为失败；修复路径识别后，原始生效值进入同一验收流程，对应默认值指控消失。

适用边界：检查器的 False 可能表示证据缺失，不必然表示参数值错误。诊断须核对实际报告及完整原脚本；缺少显式选项不等于缺陷。不能仅依据检查器 False 或修复后成功来给任意原始指控背书。

## C-D04 症状不是第二个根因，可信度 C

来源：iter10h_netlist_20261001_01，网表改写和 EQY/Scan 通过，但诊断同时报告结构时钟阻断和它导致的不可扫描，并把后者定位到原本合法的映射命令。该轮不能计诊断满分。

合法映射不会因另一个时钟/复位问题暂时阻止替换而自动变成独立故障。新增诊断必须有独立错误的命令、参数或连接；不同的错误消息和位置不自动代表不同根因。后续轮次揭示的真实原始问题可以补充，但候选脚本自己引入的错误不计为原始题目故障。

## C-D05 去重不能吞掉独立参数，可信度 C

来源：iter10h_timed_d6_20261001_01 的 C4。初始计划正确分开了 usage/off_state、si_port_format/so_port_format，核验却分别合并成一个，甚至支持理由里仍写着“独立”。最终产物通过但诊断条目丢失，不能计诊断满分。

现有去重入口禁止不同具名 defective_parameter 互相作为重复根因目标；无效归属通过原有一次核验纠正，不能在最终报告静默删除。该约束不替代语义判断：相同参数也可能对应不同端口的独立故障。错误对象名与遗漏正确对象名若由同一次替换解释，仍可作为一个根因。

## C-D06 实现偏好不是原始缺陷，可信度 C

来源：d7 C4 与 iter10h_c4_internal_single_probe。模型引用“单时钟域”断言内部时钟 single 错误；保留其他修复、仅恢复原 single 的工具试验仍全过，反证该指控。源时钟数量不蕴含 internal_clocks 策略，此约束同时适用于需求提取和配置类诊断引用；不能改个错误类别就继续主张同一无证据因果。

同类提取失败：d44 串行 T1/C5 在 Scan 前退出，模型把“伪主输入各自构成独立时钟域”两次提取为 multi，而题目另一条约束已确定 internal_clocks=none。独立伪输入域与内部时钟链策略是不同概念；纠正应保留实际题目值，并把无法表达的拓扑条目放入 uncovered，不能为通过提取而改题。d47 已让反馈显示两个冲突值，是否改善真实运行另按该版实测记录。

N03 的 d6 初始根因为缺少时钟关联，后续实际靠等价结构化简成功，最终文字却仍保留初始假设。issue_updates 允许后续证据修订同一根因/位置，原始假设和失败都保留；新层级案例 scoped19 实际覆盖了非空修订，但整题仍失败且新增根因错误，不能把机制运行当作所有诊断已准确的证明。

## C-D07 核验条目的身份与失败摘要，可信度 C

来源：d8 T2/C3。工具产物已满足运行检查，但核验把第 7 条端口命名与第 8 条初始化问题错位，随后错误去重。列表长度正确不能证明每个结论对应正确根因。d11 为输入和核验输出增加 issue_number，完整唯一核对后按编号关联；不同具名参数仍禁止互相去重。该机制有定向检查，真实回归另行记录，不自动保证语义判断正确。

final_run 为空时摘要必须明确“未发布”和实际未通过检查/未核验条目，不能直接照搬模型的“全部通过”。保留原始核验响应供追溯，不事后改写历史来充当成功。

## C-D08 分区上下文不能靠固定列或单行猜测，可信度 C

来源：`benchmarks/reused_hierarchy_20261002/qualification/first16` 与 `runs/first17`。需求表新增“层级范围”列后，旧解析器将该列当成时钟，误拒正确源时钟；已有解析器已改按明确表头读列。核验失败须先核对 expected 是否真正来自题目，不能为满足误提取的约束更改电路。

不同分区可能具有完全相同的一条声明，一处合法、另一处错误。first17 两轮均单独引用重复的 shift_1 命令，不能唯一定位，未进入修复 Scan。此时原始证据应引用从正确的 `set_current_scan_partition` 到目标命令的连续原文，保留全部中间行；不要选择第一次出现当作真实位置，也不要只靠自由文本对象名猜范围。任务引用用 `L12` 或 `L12-L14`，不是附带译写内容的 `L12: ...`。这些规则只是证据定位，不能证明所引用命令的因果解释一定成立。

## C-D09 位置参数与失败历史，可信度 C

来源：`iter10h_drc_full_ids_warning19` 和 `iter10h_drc_short_ids_ignore19` 两次无模型反事实。完整 DRC ID + Warning 命令本身合法，但有未满足题目零违例要求的残留；缩写 ID + Ignore 仍命令非法。`Invalid DRC ID for Warning` 不能解释成 Warning 一律不是合法级别。规则列表和级别分别是位置操作数 arg1/arg2；只有独立证据成立时才拆成不同根因，允许忽略不意味着必须添加忽略命令。

d44 C2 已有合法 DFTR-TIE1 Ignore，仍多报“未同时加入允许忽略的 DFTR-TIE0”。题目允许列表的合法子集本身不是配置矛盾；若某条未忽略规则确实造成违反其他硬要求的结果，必须另用原始真实证据证明该因果，不能只凭权限文本或改写缺陷类别支持它。d45 加入了对此窄场景的拒绝与既有纠正流程，不代表所有自然语言权限已被完整解析。

d45 定向真实运行在 138.062 秒通过产物检查；该拒绝条件实际触发，既有一次纠正撤回了第七条误报，最终六个原始根因均保留。接近 140 秒内部截止，不能称时间余量充足，也不是所有权限措辞的稳定通过率。

`reused_hierarchy_20261002/runs/scoped19` 在增加/删除分区时钟选择器之间振荡，实际未消除物理时钟的 DFTR1。history20 曾在 R3 获得旧 16 项结构检查通过，但后续官方手册复核发现其反相引脚关联声明不满足同波形前提，128 个 FF 的报告边沿也错误；**撤回该参考与模型结果的完整成功资格**，旧记录不改。不要重复已被同一任务实际否定的方案，也不能用任意内部时钟关联将工具放行变成波形正确的证明。

## C-D11 日志编号与 DRC 对象归属，可信度 C

来源：d25 C5 `distinct_roots_d25`、`independent_resets_20261002/runs/first27` 和 `counts28`。前者工具产物通过，但模型将日志里的 Tcl `@19` 命令编号当成原文件 L19，引用到了无关日志。核验现要求引用首行原文与真实文件行号一致，保留原有一次纠正上限；这只能防错位，不能单独证明引用内容的因果意义。

三控制小例证明，同一 DRC 规则的总数和首个示例实例可能涵盖不同控制域，不能给每个端口都套用该总数/示例。先用实际模块内连接确定实例属于哪个控制；未单独展示的域可用源代码静态证据，不能写成工具已逐域报出。`control_samples` 提供真实源文件中的控制引脚样例，是有限模块定义视图，不是展开后的完整实例集合或各域 DRC 计数。

后续轮次的总动作不能覆盖每条诊断自己的 fix_action。脚本和网表编辑完全不变、只改诊断时，可复用已执行候选的真实产物重新核验，保留独立 review 记录；不把第二次核验伪装成又一次 Scan，也不豁免任何产物或证据检查。

## C-D14 候选引用的绑定，可信度 C

来源：d37 C3，110.15 秒，工具和全部产物检查通过，但核验将 insertion_info.rpt 的 L16 与 dofile 的配置原文混写，引用不成立且剩余不足 30 秒，未发布。原始失败不补写为通过。核验接口现让模型选择当前实际文件视图中的单个 E 编号，程序按该编号展开真实文件、物理行号和原文，不让模型独立拼三个字段，也不模糊匹配或事后挪动旧引用。原始选择与实际展开都保存在核验记录；无效编号仍走既有一次纠正并在持续无效时 unresolved。
