## 实验条件

仅使用授权的 gproxy、Responses 协议及 `gpt-5.6-luna`，未调用其他模型服务、未登录或提交比赛平台。每次运行均使用新目录，保留失败和 UNKNOWN；四次运行依次进行，guided 内部并发为其默认的 3。

本机 WSL 的 `/run/user/1000` 缺失，恢复该临时目录后 Podman 可用。Docker Hub 下载 Debian 镜像持续失败；另一次通过现有镜像安装 Ubuntu `opensta` 的尝试因无可用包失败。最后通过 Debian 官方 HTTPS 下载与原 Dockerfile 同版本的 OpenSTA 包，在本机已有 dev-runtime 上安装依赖，得到实验依赖镜像 `localhost/scanscan:merged-runtime-20261107`（`c26f8dc87207`）。未覆盖原 dev-runtime。

该依赖镜像包含 OpenSTA 2.0.17、tclint 0.9.0、pyslang 12.1.0 以及已有的真实 Scan、Yosys、EQY。构建配方和下载包保留在被忽略的 `dev/results/merge_20261107_runtime/`。它是本地实验环境，不是对原多阶段 Dockerfile 完整构建成功的声明。

### guided

规划出 13 项要求，4 项 PASS、9 项 UNKNOWN。120 秒 Verify 预算耗尽后，R5 以超时结束，R6 表示没有足够已绑定证据，R7–R13 未启动。核验共 26 次模型调用、26 次工具调用；整次运行含生成共 27 次模型调用。

因此是核验未完成，不是已确认产物错误。未放宽预算或把 UNKNOWN 改成 PASS，`final_run=null`，无 `final_results/`。

### direct

完成 8 次核验模型调用、7 次证据工具调用。第 8 次调用了 `finish_verification`，但要求引用出现 `line_start=29, line_end=28` 和 `line_start=43, line_end=31`，被原有校验以 ValueError 拒绝，最终保存 UNKNOWN（`evidence_or_response_error`）。不能仅根据达到 8 次调用就把该失败归为超时。

该次最终意见还在发布前指控缺少 `final.dofile`、`decision_log.json`；它不应被直接采纳为任务 FAIL。实际状态仍为 UNKNOWN，没有发布。后续应处理最终引用纠正和发布前/后证据边界，不应降低证据校验或仅增加配额刷通过。

## 复现

在已具备输入、合法许可证和获授权 gproxy 配置的本机：

```powershell
python -X utf8 dev/run_stage.py --cases task_1/case4 task_2/case1 --output-prefix UNIQUE_BASELINE
python -X utf8 dev/run_local.py --implementation ourmethod --runtime-image localhost/scanscan:merged-runtime-20261107 --verifier guided_agent --verification-mode gate --case task_1/case4 --output UNIQUE_GUIDED
python -X utf8 dev/run_local.py --implementation ourmethod --runtime-image localhost/scanscan:merged-runtime-20261107 --verifier direct_agent --verification-mode gate --case task_1/case4 --output UNIQUE_DIRECT
```

每次更换结果名称。这里只验证两个公开案例及其中一个案例的核验对照，不代表公开 11 例回归、稳定成功率或隐藏题成绩；没有合并两套运行时内部能力，也未改写新核验器的判断规则。
