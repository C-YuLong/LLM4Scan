### 已实现

- Task 1 仍不允许改网表。Task 2 提交精确的 `netlist_edits`，只在输出目录创建工作副本；不改原输入、Liberty 或工具。

- EQY 未通过则不启动 Scan、不发布 final_results；修复循环可以收到真实证明失败。通过后仍要满足 Scan 与任务验收。
- 保留 `pre_scan_Rn.v`、原始到该轮 diff、EQY 原始日志、EQY 工作目录；最终副本为 `pre_scan_final.v`，`file_changes.lec_ref` 指向该轮证明报告。检查证明过的文件在 Scan 后没有改变。
- 诊断增加 command/drc/configuration 分类，修正“所有缺陷都必须引用任务原文”的过严旧规则；配置缺陷仍必须准确引用。
- 诊断对象位置采用实际源文件、真实行号和原始语句，拒绝歧义引用；不再将模型自由编写的层级路径直接作为最终定位。模型原始描述留在计划记录中，历史结果不篡改。
- 默认使用官方示例的 Chat Completions 接口，接收统一 URL/模型环境变量；本地 Luna 显式使用 Responses。JSON 结构由程序检查。只做了离线协议契约检查，未调用主办方真实服务。

EQY 依赖问题也已定位：官方基础镜像内有 EQY/Yosys/求解器，但缺 make，Dockerfile 已补。初次证明其实 PASS，启动器误找 status 文件导致拒绝；当前根据该版本真实 `PASS` 标记与退出码判断，失败日志保留。

## 新题与真实结果

本轮沿用 Luna。N01/N03 每例六个独立缺陷：一项真实时钟结构问题，加复位极性、扫描使能极性、链数、最大链长、跨时钟配置五项错误。同一行的链数与链长按两个独立参数问题检查。题目允许等价改写但不允许固定任意功能输入或压低检查等级。

| 记录 | 数据 FF | 结果 |
|---|---:|---|
| N01 / frozen18 | 32 | 真实 EQY + Scan 产物通过，R3；6 项真实根因之外多报“默认分区缺失”，诊断不全通过；Agent 耗时 250.22 秒 |
| N01 / repair19_diagnosis | 32 | R2；真实 EQY、Scan、独立产物验收通过；人工核对六项诊断均正确，无额外项；启动器 205.80 秒 |
| N02 / frozen18 | 96 | R3；仅改配置，未改网表，未调用 EQY；五项配置根因正确，额外默认分区诊断被最终核验否决；Agent 耗时 160.02 秒 |
| N03 / frozen19 | 128 | 同一 capability19，R2；真实 EQY、Scan 和独立产物验收通过，最终六项根因人工核对正确；启动器 206.47 秒 |

N02 出题时误把复位重汇合作为独立结构缺陷。实际正确释放复位后网络可控，无需修改网表。因此它不计为六故障网表修复通过，也不判系统漏报；保留原输入/错误 oracle 和 [审查说明](../benchmarks/netlist2/fixture_review.md)，作为不要过度修复的对照。另建 N03，不覆盖旧题。

N03 使用对偶时钟网络：正确脚本下仍有 128 个 DFTR1 和两个 DFTR8，等价改写后参考 EQY 与 Scan 都通过。它与 N01 是有关联的合成结构，不是独立工业 IP；该验证不提供隐藏题正确率估计。

N03 初始诊断还声称 internal_clocks 必须改变，最终核验以没有任务依据为由否决，最终六个真实根因保留。因此所选 N01/N03 为 12 个真实根因全命中、最终无额外根因。capability19 保留原始计划编号，N03 最终编号有空缺；后续源码只在最终发布时连续编号，拒绝项保留 `plan_issue_id` 以便追溯，不篡改旧记录。

## 默认分区误报的共性修复

N01 frozen18 错误声称必须创建 Default_Partition，修复候选真的执行 add 导致 SCAN-1920。后续修正脚本却保留这个误报，说明“产物修好了”不能证明诊断正确。

官方镜像 `/opt/dftexp_scan/share/md/cmd/add_scan_partition.md` 明确：Default_Partition 为预定义保留名，不需要且不能重新创建。已加入命令指导、诊断核验和知识条目。原始全部 FF 因其他 DRC 失败导致报告空表，不等于默认分区不存在。这不是按 N01 名字写特例。

## 知识库和技能

[knowledge/README.md](../knowledge/README.md) 是入口；[scan-insertion/SKILL.md](../knowledge/scan-insertion/SKILL.md) 是可供后续协作使用的项目技能。

依照 skill-creator 的组织原则，入口只放约束和选读路线，详细内容分为规则、控制路径、诊断、等价证明、扫描结构。每篇有检索词、出处、可信度、适用范围和边界：

- A：官方规范。
- B：官方工具说明。
- C：有真实记录的本地结论，只证明相应范围。
- D：未验证/未解决/待确认，不能作为成功依据。

同一份知识由比赛智能体的 `knowledge_search.py` 按关键词选取，保留原始可信度与限制；不依赖 Codex 技能机制，不需要向量库。参考答案、oracle、日志原文件、账号和官方资料全集不进入镜像或知识库。N02 错误出题、H05 未解决以及默认分区误报均保留为反例。

```powershell
python -X utf8 submission/knowledge_search.py "DFTR9 时钟 初始化"
python -X utf8 submission/knowledge_search.py "EQY 修改网表"
```

## 复现与版本

只评分已有产物，不重复调用模型：

```powershell
python -X utf8 dev/netlist_stage.py score --batch repair19_diagnosis --cases N01_clock_reconvergence
python -X utf8 dev/netlist_stage.py score --suite-dir benchmarks/netlist_holdout --batch frozen19 --cases N03_dual_clock
```

在新目录生成和运行；已有案例目录拒绝覆盖：

```powershell
python -X utf8 dev/netlist_stage.py prepare --suite-dir benchmarks/netlist_new --cases N01_clock_reconvergence N03_dual_clock
python -X utf8 dev/netlist_stage.py run --suite-dir benchmarks/netlist_new --batch experiment01 --cases N01_clock_reconvergence N03_dual_clock --image localhost/scanscan:capability19
```

`score` 做独立产物检查并列出预期缺陷，不把“报告数量相同”自动当作诊断正确；根因需另行人工阅读。模型只挂载当前题 input 和自己的 output，不挂载同级 oracle。

镜像 capability19：`9475280c32cdccf801eef9cb3ddad5b40bc019f8b51eca4488ee621bfecfb7d2`。

检查限于变更相关的诊断方法、接口契约、技能格式、真实等价正负例及新题闭环。首次诊断测试暴露两个旧测试缺少原始日志和新函数关键字参数，修正测试现场后 10 项通过；没有为通过测试放宽运行时证据要求。未重跑公开例或 Scan32 全集。
