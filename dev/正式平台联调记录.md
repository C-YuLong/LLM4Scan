## 设计资料稳定性与无损 JSON 压缩

继续优化时发现同一 T1/C4 网表的控制资料并不稳定：仅把 Python 的哈希种子从 1 改成 2，输出即从 52,638 字符/850 行变成 52,689 字符/863 行，摘要也不同。原因是 Liberty 引脚存放在无序集合中，而控制路径遍历有数量上限，遍历顺序会改变选中的证据。这不仅影响输入缓存，还影响同一设计的诊断复现。

本轮修改：

- 控制引脚、组合单元输入/输出引脚按固定顺序遍历，组件文件及任务文件列表也排序；不降低既有选择数量和字符预算。
- 任务提取、生成、诊断、纠错与核验使用紧凑 JSON 分隔符，去掉字段之间的无意义空格；字符串内部的源码、任务原文、行号及证据不改，落盘报告仍保留可读缩进。
- 继续保留固定缓存标识、公共前缀及末尾追加纠错的做法，不改变模型、验收规则或重试次数。
