## 本阶段实现

1. **任务书驱动的确定性验收**：从明确支持的中文句式/表格读取链数、链数上限、链长、分区配置、输出文件、时钟/使能角色、部分复位极性与配置标志。解析的是要求，不以生成脚本中的错误配置作为目标。
2. **实际报告比对**：检查分区链数、源时钟、SE、实际链长、SI/SO 格式、报告数量一致性、必需文件非空，及日志中的 DRC 降级规则是否超出任务许可。按报告表头识别报告类型，允许文件名变化。
3. **诊断与产物成功分开**：原始引用必须真实存在；相同命令上的不同根因不强行合并；明显的 runner 路径赋值和完全重复条目被拒绝。现有核验调用分别返回 `original_defect_supported` 和修复证据，无需额外模型轮次。被否决的诊断保存到 `rejected_diagnoses`。
4. **失败继续留证**：模型未返回结构化文件/行号时，该条标为未解决，不再触发 KeyError 或编造引用。支持跨轮按稳定 issue ID 关联尝试。
5. **一条命令批量回归**：顺序运行、每例独立新目录、增量摘要、重复路径保护、独立验收与运行时验收分列、用量去重；未完成批次不会被标为通过。
6. **命令语义补齐**：多分区、内部时钟、级联门控初始化、时钟闩锁关联、合法别名、默认扫描使能极性/用途；不将合法默认值当作必改错误。

使用了 3 个 Luna 子 agent，分别处理诊断、验收和批量回归。主 agent 对代码进行了集成审查、纠错、补齐实际任务书测试，并负责所有真实回归和最终交付。没有把子 agent 的“完成”声明当作验证结果。
